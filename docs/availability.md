# Availability: dry detection and hand-off

Status: design.

The failure this page exists for: a worker hits its quota, never reports, and
the orchestrator waits forever on a completion that won't come. The fix is a
watchdog **in the engine** that doesn't depend on the worker saying anything.

## Signals

Sampled about every 10 seconds per working agent. All are cheap: one screen
read and one file `stat`.

| # | Signal | Catches |
|---|---|---|
| 1 | process exited, pane closed | crashes, a CLI quitting on an auth error |
| 2 | host agent state (herdr status events; tuios `agent-state`, including `errored`) | blocked, idle, errored |
| 3 | provider errors in the conversation record ([Agents](agents.md)) | rate limit, quota, auth expired, often with a reset time |
| 3b | live retry status: OpenCode/Kilo `serve` `session.status` (`type: "retry"`); Pi json/rpc `auto_retry_start` | retry loops as they happen, before anything is written to the record |
| 4 | screen signatures: the last ~40 lines matched against the CLI's dry patterns | CLIs that print errors but don't record them |
| 5 | liveness: no screen change and no record growth for N minutes while "working" | silent hangs |
| 6 | quota before dispatch (codex, claude) | avoids sending work to a nearly dry agent |
| 7 | canary: one cheap non-interactive call | re-admitting a dry agent only; it spends quota |

## States

```
working ──(no progress 3 min)──► suspect ──(signal 3/4 matches, or 2 more min silent)──► dry
   ▲                                │                                                      │
   └──────(progress resumes)────────┘                 (reset time parsed, or backoff 15/30/60 min)
                                                                                           ▼
                                                                    canary ok ──► available
```

Transient provider errors (overloaded, connection dropped) are retried after 1,
2, 4 and 8 minutes before the agent is marked dry. A quota error with a stated
reset time skips the retries.

## Hand-off (target: under 60 seconds from dry to the next agent working)

1. **Checkpoint.** The engine commits the worktree as
   `wip(shprd): checkpoint before hand-off` and archives the ref.
2. **Mark dry** with the reason and the reset time, as an event.
3. **Pick the next** available agent in the role's order.
4. **Hand-off brief**, generated by code: the task, acceptance criteria,
   skills, `git diff --stat` since base, the last ~30 lines of the record, and
   "continue from the checkpoint; don't restart".
5. **Start the new agent in the same worktree.** If the checkpoint fails a quick
   sanity check, the task restarts from a clean worktree at the last good
   commit instead.
6. **Tell the orchestrator by event.** It may override the choice, but it
   doesn't have to act.

## Before dispatch

The engine skips any agent marked dry until its reset time, so there's no
"dispatch, wait, discover it's dry" loop. A phone card is sent only when no
agent is left for a role.
